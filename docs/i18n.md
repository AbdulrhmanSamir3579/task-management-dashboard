# Internationalisation

English and Arabic, with right-to-left layout.

## ngx-translate, not `@angular/localize`

|                      | `@angular/localize` (built in)                | ngx-translate (chosen)                          |
| -------------------- | --------------------------------------------- | ----------------------------------------------- |
| When text is applied | At build time: one build per language         | At runtime: one build, a JSON file per language |
| Switching language   | Load another build (another URL), page reload | Instantly, in place                             |
| Runtime cost         | None                                          | A lookup per text                               |
| Plurals              | ICU messages built in                         | Not built in                                    |
| Workflow             | `i18n` attributes, extracted to XLIFF files   | Keys in JSON files                              |

**Why:** the header switches language instantly, and GitHub Pages serves a single build, so runtime translation fits. It also matches the team's other Angular projects. Transloco would have worked too; consistency with those projects decided it.

## Covering ngx-translate's weak spots

| Weak spot                       | What we did                                                                                   |
| ------------------------------- | --------------------------------------------------------------------------------------------- |
| Wrong keys fail silently        | `TranslationKey` is typed from `en.json`: a wrong key fails to compile                        |
| Keys in templates aren't typed  | `npm run i18n:check` in CI fails on unknown keys and on text written directly in a template   |
| No plurals                      | `Intl.PluralRules` picks the form; Arabic has all six (zero, one, two, few, many, other)      |
| Strings go stale after a switch | `LanguageService.t()` reads the language signal, so `computed()` text rebuilds on a switch    |
| Flash of the wrong language     | An app initializer waits for the saved language; an inline script sets `lang` and `dir` early |
| Loading over HTTP               | Each language file is a code-split module: its own cached chunk, no interceptors involved     |

## Right to left

- CSS uses logical properties (`margin-inline-start`, ...), so the layout mirrors without overrides.
- Dates and numbers use `Intl` with the current locale (`ar-u-nu-latn` keeps Western digits).
- Charts are always drawn left to right, because ECharts places its SVG text badly on a right-to-left page, and are mirrored through their options instead.
- The Arabic font downloads only when Arabic text is shown.

## Not translated

Task titles, descriptions, tags and names. They are data, entered by people.
